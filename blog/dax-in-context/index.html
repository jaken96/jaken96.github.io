DAX in Context: Five Business Questions, One Sales Model

DAX functions make more sense when they have a job. This demo starts with one Northwind sales measure, then changes the evaluation context to answer five questions that a business could act on.

Drafted August 17, 2026 · Source results checked against Microsoft Northwind

The hard part is context, not syntax

A list of DAX functions did not help me understand DAX. The same measure can return a company total, a country total, or a prior-year total without changing its base formula. The model and the current context decide which rows the measure can see.

Grain

What one row represents. In FactSales, one row is one product line on one order.

Row context

The current row while an iterator such as SUMX evaluates an expression.

Filter context

The active slice of the model, such as Germany, April 1998, or one company.

The five problems below keep the sales rule stable. Each new answer comes from a deliberate change to context.

Build the model before the measures

I used the official Microsoft Northwind SQL script instead of republishing a third-party CSV mirror. The repository uses the MIT license. The source contains 91 customers, 830 orders, and 2,155 order lines dated July 4, 1996 through May 6, 1998.

I shaped the normalized source into two fact tables and five dimensions. FactSales holds line-level quantity, historical unit price, and discount. FactOrders holds one row per order, so freight and shipping dates are not repeated for every product line. Microsoft recommends clear fact and dimension roles for Power BI semantic models [Microsoft star-schema guidance; accessed 2026-08-17].

Text version of the model

  • DimDate, DimCustomer, DimEmployee, and DimShipper filter both fact tables.
  • DimProduct filters FactSales. I flattened the small category table into this dimension.
  • FactSales and FactOrders have no direct relationship.
  • DimDate is a continuous calendar and is marked as the model's date table.

Question 1

What are net sales after line discounts?

The source stores quantity, unit price, and discount on each order line. I must calculate the discounted value at that grain before I add the lines.

First attempt: multiply the totals

Net Sales (wrong) :=
    SUM ( FactSales[Quantity] )
        * SUM ( FactSales[Unit Price] )
        * ( 1 - SUM ( FactSales[Discount] ) )

This formula multiplies unrelated column totals. It can also subtract several line-level discount rates from one. The result has no useful business meaning.

Correct measure: calculate each line first

Net Sales :=
SUMX (
    FactSales,
    FactSales[Quantity]
        * FactSales[Unit Price]
        * ( 1 - FactSales[Discount] )
)

SUMX evaluates the expression once for each visible row in FactSales, then adds the results. That iteration creates the row context this rule needs [Microsoft SUMX reference; accessed 2026-08-17].

Validation checkpoint: Across all 2,155 source lines, the measure returns $1,265,793.04. I calculated the same value independently from the Northwind script.

Question 2

Which German companies bought the most in 1997?

The full request is precise: show 1997 net sales to German customers, group the result by purchasing company, and put the largest value first.

First attempt: return one hard-coded total

German Sales 1997 (incomplete) :=
CALCULATE (
    [Net Sales],
    DimCustomer[Country] = "Germany",
    YEAR ( FactSales[Order Date] ) = 1997
)

This measure gives one scalar value. It does not produce the requested company rows or a stable sort order. It also filters a fact-table date instead of using the model's calendar.

Correct query: define, filter, group, and sort

DEFINE
    MEASURE FactSales[Net Sales] =
        SUMX (
            FactSales,
            FactSales[Quantity]
                * FactSales[Unit Price]
                * ( 1 - FactSales[Discount] )
        )

EVALUATE
VAR StartDate = DATE ( 1997, 1, 1 )
VAR EndDate = DATE ( 1997, 12, 31 )
VAR TargetCountry = "Germany"
RETURN
    CALCULATETABLE (
        SUMMARIZECOLUMNS (
            DimCustomer[Company Name],
            "Sales Volume", [Net Sales]
        ),
        KEEPFILTERS ( DimCustomer[Country] = TargetCountry ),
        DATESBETWEEN ( DimDate[Date], StartDate, EndDate )
    )
ORDER BY
    [Sales Volume] DESC,
    DimCustomer[Company Name] ASC

I run this in Power BI's DAX query view. A DAX query requires EVALUATE; its optional DEFINE block can add a query-scoped measure [Microsoft DAX query view; accessed 2026-08-17].

CALCULATETABLE evaluates a table expression in a modified filter context. KEEPFILTERS makes the country condition intersect with an existing country filter instead of replacing it. DATESBETWEEN supplies an inclusive date range from the marked calendar. SUMMARIZECOLUMNS creates one row per company, and ORDER BY makes the output deterministic [Microsoft CALCULATETABLE reference; accessed 2026-08-17] [Microsoft KEEPFILTERS reference; accessed 2026-08-17].

Question 3

What share of selected-country sales came from each company?

The numerator is already correct: [Net Sales] in the current company row. The denominator needs the same date and country filters without the company-row filter.

First attempt: remove every customer filter

Company Share (wrong) :=
DIVIDE (
    [Net Sales],
    CALCULATE (
        [Net Sales],
        REMOVEFILTERS ( DimCustomer )
    )
)

This denominator removes the company filter, but it also removes Germany. It answers “share of all customer sales,” not “share of German sales.”

Correct measure: remove only the company row

Company Share of Selected Country :=
VAR CompanySales = [Net Sales]
VAR CountrySales =
    CALCULATE (
        [Net Sales],
        REMOVEFILTERS ( DimCustomer[Company Name] )
    )
RETURN
    DIVIDE ( CompanySales, CountrySales )

REMOVEFILTERS targets one column, so the country and date context remain. DIVIDE returns blank when the denominator is zero or blank unless I provide another result [Microsoft REMOVEFILTERS reference; accessed 2026-08-17] [Microsoft DIVIDE reference; accessed 2026-08-17].

Validation checkpoint: With Germany and 1997 selected, QUICK-Stop contributes 52.09% of the country's net sales.

Question 4

How does each company rank inside the current selection?

A rank should react to report filters. If a reader selects three companies, those three should rank first through third.

First attempt: ignore the company selection

Company Rank (wrong) :=
RANKX (
    ALL ( DimCustomer[Company Name] ),
    [Net Sales],
    ,
    DESC,
    DENSE
)

ALL removes every filter from the company-name column, including a company slicer. The rank still compares each visible row with companies the reader chose to exclude.

Correct measure: rank the visible set

Company Rank in Selection :=
IF (
    ISINSCOPE ( DimCustomer[Company Name] ),
    RANKX (
        ALLSELECTED ( DimCustomer[Company Name] ),
        [Net Sales],
        ,
        DESC,
        DENSE
    )
)

ALLSELECTED removes the current company-row filter while it retains filters from outside the row, such as slicers. RANKX evaluates [Net Sales] for each company in that set. ISINSCOPE prevents the total row from pretending to be another company [Microsoft ALLSELECTED reference; accessed 2026-08-17] [Microsoft RANKX reference; accessed 2026-08-17] [Microsoft ISINSCOPE reference; accessed 2026-08-17].

With Germany and 1997 selected, the measure gives QUICK-Stop rank 1 and Drachenblut Delikatessen rank 11. If a slicer narrows the visible companies, the dense ranks close around that selection.

Question 5

How did sales change from the same period one year earlier?

A prior-year comparison must shift the active date set. Replacing one year label is not enough for an arbitrary day, month, or quarter selection.

First attempt: replace only the year

Net Sales PY (wrong) :=
CALCULATE (
    [Net Sales],
    DimDate[Year] = MAX ( DimDate[Year] ) - 1
)

This can appear to work on a year-only visual. It can fail when another date column still filters the current period, and it does not express the intended shift of the selected dates.

Correct measures: shift the date context and divide safely

Net Sales PY :=
CALCULATE (
    [Net Sales],
    DATEADD ( DimDate[Date], -1, YEAR )
)

Net Sales YoY % :=
VAR CurrentSales = [Net Sales]
VAR PriorSales = [Net Sales PY]
RETURN
    DIVIDE ( CurrentSales - PriorSales, PriorSales )

DATEADD returns the active dates shifted one year back. The base measure then evaluates under that new date context [Microsoft DATEADD reference; accessed 2026-08-17].

Validation checkpoint: April 1998 net sales are $123,798.68, compared with $53,032.95 in April 1997. The measure returns 133.44% growth.

Coverage warning: Northwind ends on May 6, 1998. A full-year 1998 versus 1997 comparison would mix a partial year with a complete year. Correct DAX cannot repair a poorly framed comparison.

The reusable pattern

These measures are easier to maintain because each one has one job.

Business question Stable calculation Context change
Net salesLine value after discountSUMX creates row context.
Germany in 1997[Net Sales]Country and date filters constrain the rows.
Company share[Net Sales]Remove only the company-name filter for the denominator.
Company rank[Net Sales]Compare the row with companies kept by the report selection.
Year-over-year growth[Net Sales]Shift the active date set back one year.

The functions matter, but the model and the business question come first. Once the grain is clear and the base measure is correct, most of the work is deciding which filters to keep, replace, or remove.

Checks I would keep with the project

  1. Reconcile all net sales to $1,265,793.04.
  2. Confirm that the 11 German company rows sum to $117,320.16 for 1997.
  3. Test zero-discount, discounted, and multi-line orders by hand.
  4. Change the company slicer and confirm that rank follows the visible selection.
  5. Test a period with no prior-year data and confirm that the growth measure returns blank.
  6. Show the source's minimum and maximum order dates anywhere a reader could mistake partial periods for complete ones.

A report page can make these answers attractive. A saved DAX query makes them testable. I want both.
